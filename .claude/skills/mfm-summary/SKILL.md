# MFM summary

Process a Monthly Focus Meeting after it happens. Combines the Granola meeting transcript with the MFM review prep to produce a complete post-meeting summary with coverage tracking.

## Trigger phrases

- `mfm summary: [squad] [month]`
- `post mfm: [squad] [month]`
- "summarise the mfm"
- "what came out of the mfm?"

## Process

### Step 1: Find MFM prep/review

Look for existing MFM review output at: `Work/Process/MFM/{Month}/{squad}_mfm_review.md`

If found, load it - this contains the dimensional analysis, key questions, and concerns raised pre-meeting. If not found, note this and continue without cross-referencing.

### Step 2: Find the meeting in Granola

1. Search Granola: `mcp__granola__list_meetings(time_range="this_week")` or `last_week`
2. Match by squad name or "monthly focus meeting" in the title
3. **Present the match to the user and confirm before proceeding:**
   - Show: meeting title, date, duration, attendees
   - Ask: "Is this the right meeting?"
   - If multiple matches, show options and ask which one
   - If no match, ask user for the meeting date or offer manual input
4. Once confirmed, get the full summary: `mcp__granola__get_meetings(meeting_ids=["<id>"])`
5. Get the transcript for deeper analysis: `mcp__granola__get_meeting_transcript(meeting_id="<id>")`

### Step 3: Extract key content from transcript

From the Granola transcript and summary, extract:
- **Decisions made** - what was decided, rationale, who made it
- **Actions assigned** - owner, action, timing
- **Changes to plan** - anything that shifted from the pre-read
- **Follow-up items** - things needing further work
- **Key discussion points** - topics that got significant airtime

### Step 4: Cross-reference with MFM prep

If the MFM review was loaded in Step 1, cross-reference to produce:

**Covered in meeting:**
- Which of the "Key questions to ask" were addressed, and what the answers were
- Which concerns from the dimensional analysis were discussed
- Which blockers/asks got airtime

**Still outstanding:**
- Questions from the prep that were NOT raised or answered
- Concerns that remain unaddressed
- Gaps identified in the review that weren't discussed

**New items surfaced:**
- Topics, decisions, or concerns that came up in the meeting but were NOT in the pre-read

### Step 5: Generate summary

Create file at: `Work/Process/MFM/{Month}/{squad}_mfm_summary.md`

**Output structure:**

```markdown
# MFM Summary: [Squad] - [Month]

**Date:** [Meeting date]
**Attendees:** [List]
**MFM prep reviewed:** [Yes/No - link to review file if yes]

## Decisions made
- [Decision 1] - [rationale]
- [Decision 2] - [rationale]

## Actions
- [ ] [Owner]: [Action] (by [date])
- [ ] [Owner]: [Action] (by [date])

## Changes to plan
- [What changed from the pre-read plan and why]

## Coverage vs prep

### Addressed
- [Question/concern from prep] - [outcome/answer]

### Still outstanding
- [Question/concern from prep that wasn't covered] - [suggested follow-up]

### New items surfaced
- [Topic not in the pre-read that emerged in discussion]

## Follow-up required
- [Items needing follow-up with owner if known]

---
**Slack-ready summary:**

MFM Summary - [Squad] [Month]:
* [Key decision 1]
* [Key decision 2]
* Actions: [Owner] to [action]
* Outstanding: [Key unresolved item if any]

---
Generated by MFM Agent
```

If no MFM prep was available, omit the "Coverage vs prep" section entirely.

### Step 6: Create items in Julie

For each extracted item, create via `./pos`:
- **Actions:** `./pos "new action: [action title] assignee: [Person] details: [context from MFM] due: [date]"`
- **Tasks for Chris:** `./pos "new task: [task title] details: [context from MFM] due: [date]"`
- **Outstanding items from prep:** `./pos "new task: Follow up on [topic] with [squad] details: Not covered in MFM - [context from prep review] due: [date]"`

**Before creating items:** Show the user what will be created and confirm.

### Step 7: Present and offer next steps

1. Show the full summary in the conversation
2. Confirm the file was saved and where
3. List items created
4. Offer: "Want me to send the Slack summary to a channel?"
5. Save to memory for trend tracking

## Guidelines

- **Confirm the Granola meeting match** before doing any processing
- **Exclude sensitive content from Slack summaries:** Personal feedback, performance observations, compensation, HR matters
- **Be specific with timing:** "by Friday", "this week", "end of month" - not vague
- **Focus on outputs not discussion:** What was decided and who does what, not a play-by-play
- **Slack format:** Use bullets (*) not dashes, include person names with actions, keep it standalone

## Error handling

- **Granola meeting not found:** Ask user for meeting date, offer to search a different time range, or accept manual input
- **MFM prep not found:** Continue without cross-referencing, note this in the output
- **Confluence unavailable:** Not needed for summary - this skill works from Granola, not Confluence
