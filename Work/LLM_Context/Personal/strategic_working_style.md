# Strategic working style

How Chris approaches strategic initiatives, product development, and cross-functional leadership. Use this as context when helping Chris scope, plan, or communicate on strategic work.

## Core strategic approach

- Challenge assumptions before accepting framing - ask "why this way?" before "how do we do this?" Push for braver thinking.
- Big thinking, fast validation - think ambitiously about outcomes, but get work live quickly to learn. Be brave enough to set a bold direction AND brave enough to descope ruthlessly to test it. Accept gaps when the goal is learning. The failure mode isn't shipping something imperfect - it's spending months perfecting something that turns out to be wrong.
- Guardrails over directives - set boundaries and principles, let teams find their own path within them. Default mode is strategic direction, not execution detail.
- Delegate execution, retain strategic lens - stay out of the how, stay close to the why. Uses wireframes and sketches as a communication tool to articulate ideas, not to prescribe solutions. See growth_patterns.md Pattern 7 for the known tension here.
- Bias toward action over analysis paralysis - imperfect movement beats perfect plans.

## Non-negotiables for product development

- Experiments, not launches - if it's not instrumented to learn from, it's not ready
- Hypothesis vs prediction distinction: a hypothesis is a falsifiable belief statement, a prediction is "If... then..." - know which you're making. Common failure mode in others: defining a prediction and calling it a hypothesis.
- Domain team autonomy - teams closest to the problem make the decisions
- Teams should be able to push to the codebase themselves
- PR review SLAs matter - slow reviews kill velocity and morale
- Instrumentation is foundational, not a follow-up - if you can't measure it, you can't learn from it
- Data honesty over headline optimism - celebrate momentum but insist teams see the full picture

## What Chris brings vs delegates

Chris brings:
- PLG lens - how does this drive self-serve adoption, activation, and expansion?
- Experimentation framework - what are we testing, how do we know it worked, what's the next bet?
- Strategic guardrails - the boundaries and principles that keep work aligned without micromanaging

Chris delegates:
- Domain expertise - trust the specialists in their area
- UX execution - set the bar for outcomes, let designers own the solution. May sketch or wireframe to communicate an idea, but this is to stimulate thinking not prescribe.
- Technical architecture - understand it enough to challenge, not enough to prescribe

## Communication in cross-org work

- Acknowledge before point-making - show you've heard and understood before redirecting
- Diagnose whether the problem is disagreement or comprehension before responding - the fix is different (see growth_patterns.md Pattern 3)
- Slack tone awareness - written words land harder than spoken ones; re-read before sending (see growth_patterns.md Pattern 2)
- Be direct but not blunt - clarity is kind, abruptness is not
